# 前言

> **"让 UI 回归声明，让逻辑回归纯粹，让 Rust 桌面开发拥抱每一位前端工程师。"**

## 为什么要写这本书

Rust 生态在过去数年完成了从"系统编程语言"到"全栈语言"的跨越。在桌面 UI 领域，Zed 编辑器团队开源的 GPUI 框架以 GPU 加速、混合即时/保留模式的渲染能力，证明了 Rust 完全可以支撑工业级桌面应用。然而，GPUI 原生的链式调用 API 把 UI 结构、样式、事件、业务逻辑全部塞进同一个 Rust 文件，带来了三个长期痛点：

1. **UI 与逻辑深度耦合**——结构、样式、事件、状态交织，难以审查与维护；
2. **设计师无法参与**——非工程师无法阅读 Rust 链式调用；
3. **缺乏标准化**——每个项目各自为政，无法沉淀设计资产。

RML（Rust Markup Language）正是为解决这三件事而生。它把 WPF XAML 的 MVVM 设计精髓与 HTML 的语法亲和力结合起来，通过 `.rml`（独立标记文件）+ `.rml.rs`（纯 Rust 业务逻辑）的文件级分离，把 GPUI 的能力释放给更广泛的开发者群体。

本书的使命，是帮助每一位读者从零开始，**深进浅出**地掌握 RML 框架的产品形态，理解其设计哲学，最终成为能够独立设计复杂桌面应用的 RML 开发高手。

## 本书写给谁

| 读者画像            | 你将获得什么                                            |
| --------------- | --------------------------------------------------- |
| **Web 前端工程师**  | 用熟悉的 HTML 语法进入 Rust 桌面开发，零语法学习成本                   |
| **Rust 后端工程师** | 学会把 GPUI 的渲染能力以 MVVM 方式组织，写出可维护的桌面 UI              |
| **UI/UX 设计师**  | 直接编辑 `.rml` 文件产出可运行的设计稿，与工程师并行工作                   |
| **团队技术负责人**    | 建立标准化的 UI 开发流程，让设计资产可沉淀、可复用、可审查                    |
| **跨平台迁移者**     | 从 WPF / Vue / React / SwiftUI 迁移而来，找到 Rust 桌面的对应心智 |

## 本书的结构

本书遵循**渐进式披露**原则编排：从理念到语法，从语法到绑定，从绑定到组件，从组件到架构，最终落到实战。每一章都建立在前一章之上，但每一章也独立成篇，方便查阅。

- **第一部分 · 起步**（第 1 章）：建立对 RML 的整体认知，跑通第一个应用。
- **第二部分 · 标记与绑定**（第 2 ~ 3 章）：掌握 `.rml` 的全部语法与数据绑定机制。
- **第三部分 · 逻辑与事件**（第 4 ~ 5 章）：掌握 `.rml.rs` 的宏系统与事件流。
- **第四部分 · 组件与样式**（第 6 ~ 7 章）：掌握自定义组件封装与样式系统。
- **第五部分 · 生命周期与架构**（第 8 ~ 9 章）：掌握生命周期管理、职责划分与架构原则。
- **第六部分 · 高级与实战**（第 10 ~ 11 章）：掌握性能优化、调试、热重载与实战案例。

## 阅读约定

- **代码块**：`.rml` 文件以 HTML 语法高亮显示，`.rml.rs` 文件以 Rust 语法高亮显示，生成代码以注释标注。
- **图标约定**：
  - 💡 **提示**：补充说明或最佳实践
  - ⚠️ **注意**：常见陷阱与避坑指南
  - 🔧 **进阶**：深入实现细节
  - 📋 **清单**：可对照执行的检查项
- **版本说明**：本书内容基于 RML 设计文档 v1.0 编写，对应 GPUI 锁定的 git rev。
